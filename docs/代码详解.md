# 后端代码详解（com.campus.kb）

> 对应版本 0.2.0，共 **40 个 Java 文件**。
> 每个类先讲职责和数据流，再逐个方法说明：**做什么 / 参数 / 返回 / 异常 / 副作用**。
> Lombok 自动生成的 getter/setter/构造器不单独列出，只在实体类里说明。

---

## 0. 全局视图

### 0.1 分层

```text
Controller（HTTP 入参/出参）      AuthController · ChatController · FileController · HealthController
        │
Service（业务编排）               AuthService · ChatService · FileService · FileIngestService
        │                          FileStorageService · PromptBuilder · GuardService · VectorStoreService
        │
Repository（JPA）                 UserRepository · KnowledgeFileRepository
        │                          ChatConversationRepository · ChatMessageRepository
        │
外部依赖                          MySQL（元数据） · Chroma（向量） · OpenAI 兼容 API（对话/向量）
```

- **Controller 只做三件事**：接参数、取当前登录人、调 Service；不写业务判断。
- **Service 之间单向依赖**：Chat → File → Storage/Ingest → Vector；不会反向调用。
- **没有 @Transactional**：每一步都是独立的 `save`，失败时靠状态字段（`PENDING/PROCESSING/READY/FAILED`）兜底。

### 0.2 三条主链路

**登录**：`POST /api/auth/login` → AuthController → AuthService.login（BCrypt 校验）→ JwtService.generate → 返回 token。

**上传**：`POST /api/file/upload` → FileService.upload（落盘 + 去重 + 建 PENDING 记录）→ **立即返回** → 异步 FileIngestService.processAsync（Tika 解析 → 切分 → Embedding → 写 Chroma → READY）。

**提问**：`POST /api/chat/ask` → ChatService.ask → GuardService 意图判断 → VectorStoreService.search（按 `accessOwnerId` 过滤）→ PromptBuilder 拼上下文 → ChatModel 调模型 → 保存回答 + 引用 → 返回。

### 0.3 包与文件

| 包 | 文件数 | 职责 |
|---|---|---|
| `auth` | 7 | 注册登录、JWT 签发与校验、Spring Security 配置 |
| `chat` | 12 | 问答编排、提示词、护栏、会话/消息实体 |
| `file` | 9 | 上传、落盘、Tika 解析、向量入库、权限 |
| `rag` | 1 | Chroma 读写与权限过滤 |
| `config` | 4 | 配置绑定、模型 Bean、异步线程池、管理员初始化 |
| `user` | 3 | 用户实体、角色、Repository |
| `common` | 3 | 业务异常、全局异常处理、健康检查 |
| 根 | 1 | 启动类 |

## 1. 启动与配置（`config` + 根类）

### 1.1 `CampusKbApplication.java`（根包）

启动类，17 行。

- **类注解**
  - `@SpringBootApplication(exclude = UserDetailsServiceAutoConfiguration.class)`：排除 Spring Security 的默认用户自动配置。不排的话启动日志会打印一个随机密码的 `user` 账号，且和我们自己的 JWT 体系冲突。
  - `@EnableConfigurationProperties(AppProperties.class)`：把 `app.*` 配置绑定到 POJO（等价于在 AppProperties 上加 `@Component`，这里集中声明）。
  - `@EnableAsync`：开启 `@Async`，`FileIngestService.processAsync` 依赖它。
- **`main(String[] args)`**：`SpringApplication.run(...)`，无额外逻辑。

### 1.2 `config/AppProperties.java`

`@ConfigurationProperties(prefix = "app")` + Lombok `@Data`，是**整个项目唯一的配置入口**。

结构：

| 属性 | 字段 | 默认值 / 来源 |
|---|---|---|
| `app.auth` | `jwtSecret` | `${JWT_SECRET}`，空则启动时随机 |
| | `tokenExpireHours` | 168 |
| | `allowRegistration` | true |
| | `adminUsername` / `adminPassword` / `adminDisplayName` | admin / admin123456 / 系统管理员 |
| `app.storage` | `uploadDir` | `./uploads`（Docker 里是 `/app/uploads`） |
| | `maxFileMb` | 50（application.yml 写死） |
| `app.rag` | `store` | chroma（local profile 改 memory） |
| | `collection` | campus_kb |
| | `chunkSize` / `chunkOverlap` | 500 / 80 |
| | `topK` / `minScore` / `maxContextChars` | 6 / 0.30 / 7000 |
| | `historyMessages` | 8（带进提示词的历史条数） |
| `app.ai.chat` | `baseUrl` / `apiKey` / `model` | 百炼兼容地址 / 空 / qwen-plus |
| | `temperature` / `maxTokens` / `timeoutSeconds` | 0.2 / 1500 / 120 |
| `app.ai.embedding` | `baseUrl` / `apiKey` / `model` | 百炼 / 空 / text-embedding-v3 |
| | `dimensions` / `sendDimensions` / `batchSize` | 1024 / true / 10 |
| `app.ai.chroma` | `baseUrl` / `timeoutSeconds` | http://localhost:8000 / 30 |

- 方法全部由 Lombok 生成（`getAuth()`、`getRag()`…）。
- 嵌套静态类：`Auth`、`Storage`、`Rag`、`Ai`、`Ai.Chat`、`Ai.Embedding`、`Ai.Chroma`，字段默认值写在 Java 里，环境变量只在 `application.yml` 的 `${}` 占位符中出现。

### 1.3 `config/LangChainConfig.java`

把 LangChain4j 的“接口”变成 Spring Bean。

- **`chatModel(AppProperties) → ChatModel`**
  - 取 `app.ai.chat`；`apiKey` 为空时填 `"not-configured"`（OpenAI 客户端不接受 null，但空 key 会让每次请求 401，所以真正的兜底在 ChatService.ensureModelConfigured）。
  - `OpenAiChatModel.builder()`：baseUrl、modelName、temperature、maxTokens、timeout、`maxRetries(1)`、关闭请求/响应日志（避免把用户问题打进日志）。
- **`embeddingModel(AppProperties) → EmbeddingModel`**
  - key 取值顺序：`embedding.apiKey` → 为空则回退 `chat.apiKey` → 再为空用 `"not-configured"`。
  - 只有 `sendDimensions=true` 且 `dimensions>0` 时才调用 `builder.dimensions(...)`（Ollama 等不支持该参数的服务要关掉）。
  - `maxSegmentsPerBatch(batchSize)`：百炼 embedding 单次最多 10 条，这里按配置分批。
- **`inMemoryEmbeddingStore()`**：`@ConditionalOnProperty(app.rag.store=memory)`，返回 `InMemoryEmbeddingStore`（local profile / 测试用）。
- **`chromaEmbeddingStore(AppProperties)`**：`matchIfMissing=true`，默认生效；`ChromaApiVersion.V1` + baseUrl + collectionName + timeout。
- **`documentParser()`**：`ApacheTikaDocumentParser`，支持 PDF/DOCX/PPTX/TXT/MD 的文本抽取。
- **`documentSplitter(AppProperties)`**：`DocumentSplitters.recursive(chunkSize, chunkOverlap)`，按字符递归切分，优先段落、再句子。

### 1.4 `config/AsyncConfig.java`

- **`fileTaskExecutor() → ThreadPoolTaskExecutor`**：核心 2、最大 4、队列 100、线程名前缀 `file-ingest-`。上传解析是 IO+CPU 混合型任务，2~4 个并发足够，队列防止突发上传把内存打满。

### 1.5 `config/DataInitializer.java`

`CommandLineRunner`，应用启动完成后执行一次。

- **`run(String... args)`**
  1. `existsByRole(ADMIN)` 为真 → 直接返回（**只在库里没有管理员时初始化**，所以改 `.env` 的 `ADMIN_PASSWORD` 对已有库无效）。
  2. 用户名 `trim().toLowerCase()`。
  3. 密码为空 → 打警告并跳过。
  4. 用户名已存在但不是管理员 → 打警告并跳过（避免把普通学生提权）。
  5. 创建 `User`：BCrypt 加密密码、`Role.ADMIN`、显示名取配置，保存并打日志。

## 2. 认证与安全（`auth`）

### 2.1 `auth/AuthController.java`

`@RestController @RequestMapping("/api/auth")`，4 个接口。

- **`register(@Valid RegisterRequest) → AuthResponse`**：`@PostMapping("/register")` + `@ResponseStatus(CREATED)`，注册成功直接返回 token（注册即登录）。
- **`login(@Valid LoginRequest) → AuthResponse`**：`POST /login`。
- **`me(@AuthenticationPrincipal UserPrincipal) → UserDto`**：`GET /me`，返回当前登录人信息。
- **`changePassword(principal, @Valid ChangePasswordRequest) → Map`**：`POST /change-password`，返回 `{success, message}`。

### 2.2 `auth/AuthDtos.java`

纯 DTO 容器（`final` 类 + 嵌套 record），**没有任何逻辑**，校验注解就是接口契约。

| record | 字段与校验 |
|---|---|
| `RegisterRequest` | `username`：3–32 位字母/数字/下划线；`password`：8–128；`displayName`：≤40，可空 |
| `LoginRequest` | `username` / `password` 非空 |
| `ChangePasswordRequest` | `oldPassword` 非空；`newPassword` 8–128 |
| `UserDto` | `id, username, displayName, role`；静态 `from(User)` 做实体→DTO 转换 |
| `AuthResponse` | `token, user` |

### 2.3 `auth/AuthService.java`

- **`register(RegisterRequest) → AuthResponse`**
  1. `allowRegistration=false` → 403。
  2. 用户名规范化（trim + 小写），`existsByUsername` → 409。
  3. 建用户：BCrypt 加密、默认角色 `STUDENT`、`displayName` 为空则用用户名。
  4. 保存后立刻签发 JWT，返回 token + 用户信息。
- **`login(LoginRequest) → AuthResponse`**
  1. 用户名同样规范化后查库；查不到或密码不匹配都返回 **401「用户名或密码错误」**（不区分，防用户名枚举）。
  2. 校验通过签发 token。
- **`current(UserPrincipal) → UserDto`**：按 `principal.id()` 重新查库（保证拿到最新昵称/角色），查不到 401。
- **`changePassword(principal, old, new)`**
  1. 查用户；旧密码不匹配 → 400「原密码不正确」。
  2. 新旧相同 → 400。
  3. BCrypt 重新编码保存。**注意：改密不会让已签发的旧 token 失效**（JWT 无状态，除非轮换 `JWT_SECRET`）。

### 2.4 `auth/JwtService.java`

JWT 的签发与校验，密钥在构造函数里一次性准备好。

- **构造器 `JwtService(AppProperties)`**
  - `jwtSecret` 为空 → 用随机 UUID 拼一个（日志警告；**重启后所有登录态失效**）。
  - 字节长度 < 32 → 先做一次 SHA-256 拉长（HS256 要求 256 bit）。
  - `Keys.hmacShaKeyFor(bytes)` 得到 `SecretKey`；有效期 `max(1, tokenExpireHours)` 小时。
- **`generate(User) → String`**：`subject` = 用户 id，claims 带 `username`、`role`，`issuedAt` / `expiration`，HS256 签名。
- **`parse(String) → Claims`**：`Jwts.parser().verifyWith(key)`，签名错/过期都会抛异常（由过滤器捕获）。

> 密钥泄露 = 别人可以伪造任意用户（含管理员）的 token，所以 `.env` 的 `JWT_SECRET` 必须随机且不进 Git。

### 2.5 `auth/JwtAuthenticationFilter.java`

`OncePerRequestFilter`，每个请求执行一次，**只负责“认出人”，不负责“拦人”**（拦截交给 SecurityConfig）。

- **`doFilterInternal(request, response, chain)`**
  1. 读 `Authorization`，必须以 `Bearer ` 开头。
  2. `jwtService.parse(token)` → 取 `subject` 转 `Long userId`。
  3. 查库拿 `User`；查不到就当未登录。
  4. 构造 `UserPrincipal`，放进 `UsernamePasswordAuthenticationToken`，权限 `ROLE_ADMIN` / `ROLE_STUDENT`，写入 `SecurityContextHolder`。
  5. 任意异常 → `clearContext()` 后继续（最终由 Security 返回 401 JSON，而不是抛 500）。
  6. 无论有没有 token，最后都 `chain.doFilter(...)`。

### 2.6 `auth/SecurityConfig.java`

- **`passwordEncoder() → PasswordEncoder`**：BCrypt（默认强度 10）。
- **`corsConfigurationSource() → CorsConfigurationSource`**
  - `allowedOriginPatterns("*")`：允许直接用浏览器打开 `index.html` 时跨域访问后端。
  - 方法 GET/POST/PUT/DELETE/OPTIONS；请求头全放开；暴露 `Content-Disposition`（下载时要读文件名）；`allowCredentials=false`。
- **`filterChain(HttpSecurity, JwtAuthenticationFilter) → SecurityFilterChain`**
  - 关 CSRF（无状态 API + JWT，不需要）。
  - 无状态：`SessionCreationPolicy.STATELESS`。
  - 放行：`/`、`/index.html`、`/favicon.ico`、`/error`、`/api/auth/login`、`/api/auth/register`、`/api/health`、`/actuator/health*`、所有 OPTIONS。
  - 其余 `authenticated()`。
  - 401/403 用 `writeJson` 输出统一 JSON（`{"message": "请先登录"}`），不会返回 Spring 默认的 HTML 错误页。
  - `addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)`。
- **`writeJson(response, status, message)`**（private）：设置 UTF-8 + `application/json`，手写一个最简 JSON。

### 2.7 `auth/UserPrincipal.java`

`record UserPrincipal(Long id, String username, String displayName, String role)`。
Spring Security 的“当前登录人”，Controller 里用 `@AuthenticationPrincipal` 直接拿到；**只放必要字段，不含密码哈希**。

### 2.8 `user/User.java`

实体，表 `users`。

| 字段 | 列 | 说明 |
|---|---|---|
| `id` | 主键 | 自增 |
| `username` | `username` | 唯一索引 `idx_users_username`，≤64，存小写 |
| `passwordHash` | `password_hash` | BCrypt 结果，≤100 |
| `displayName` | `display_name` | 昵称，≤120 |
| `role` | `role` | 枚举字符串 `STUDENT` / `ADMIN` |
| `createdAt` | `created_at` | `@PrePersist` 自动填 |

- **`prePersist()`**：首次插入时补 `createdAt`。

### 2.9 `user/Role.java`

`enum Role { STUDENT, ADMIN }`，权限判断里直接比较字符串 `"ADMIN"`。

### 2.10 `user/UserRepository.java`

- **`findByUsername(String)`**：登录用。
- **`existsByUsername(String)`**：注册查重。
- **`existsByRole(Role)`**：初始化管理员前判断“库里有没有管理员”。

## 3. 文件与知识库（`file`）

### 3.1 `file/FileController.java`

`@RequestMapping("/api/file")`，7 个接口。**全部要求登录**（SecurityConfig 里没有放行）。

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| `upload` | `POST /upload` | `file`（multipart）+ `visibility`（可选） | `UploadResponse` |
| `myList` | `GET /myList` | — | `List<FileDto>` 我上传的 |
| `publicList` | `GET /publicList` | — | 所有公共资料 |
| `accessibleList` | `GET /accessibleList` | — | 公共 + 我的私有 |
| `delete` | `DELETE /{fileId}` | 路径参数 | `{success, message}` |
| `reindex` | `POST /{fileId}/reindex` | 路径参数 | `FileDto` |
| `download` | `GET /{fileId}/download` | 路径参数 | 文件流 |

- **`download`** 额外做两件事：`ContentDisposition.attachment().filename(originalName, UTF_8)` 保证中文文件名不乱码；`MediaType.APPLICATION_OCTET_STREAM` 强制下载。
- Controller 里没有任何权限判断，全部委托给 `FileService`（这样 Service 层也能被别处安全复用）。

### 3.2 `file/FileDtos.java`

- **`FileDto(id, ownerId, filename, fileType, size, status, visibility, chunkCount, ownerName, errorMessage, createdAt)`**
  - `from(KnowledgeFile)`：实体转前端 DTO，`status`/`visibility` 用 `enum.name()` 字符串。
  - 注意字段叫 `filename`，对应实体的 `originalName`。
- **`UploadResponse(success, message, file)`**：上传接口的返回体，`message` 是需求文档要求的那句固定文案。

### 3.3 `file/FileService.java`

文件业务的总入口，**权限模型就实现在这个类里**。

- **`upload(MultipartFile, String visibility, UserPrincipal) → UploadResponse`**
  1. 只有**管理员**且显式传 `public` 才能创建公共资料；其余一律 `PRIVATE`（学生无法上传公共资料）。
  2. `storageService.store()` 落盘并算 SHA-256。
  3. 去重：公共资料按 `sha256 + PUBLIC` 查；私有资料按 `sha256 + ownerId + PRIVATE` 查。重复 → 删掉刚落的盘 → 409。
  4. 组装 `KnowledgeFile`（owner、visibility、原名、存储名、类型、大小、sha256、状态 `PENDING`、chunkCount=0）并保存。
  5. `ingestService.processAsync(fileId)` **异步**解析；接口立即返回“已接收”。
- **`myList(principal) → List<FileDto>`**：按 `ownerId` 查，创建时间倒序。
- **`publicList() → List<FileDto>`**：`visibility=PUBLIC`。
- **`accessibleList(principal) → List<FileDto>`**：`PUBLIC or ownerId=我`，前端选择“针对哪些资料提问”时用。
- **`getAccessible(fileId, principal) → KnowledgeFile`**：不存在 → 404；`canView` 不通过 → 也返回 **404**（刻意不用 403，避免泄露“别人有这份私有资料”）。
- **`delete(fileId, principal)`**
  1. `getManageable` 校验（本人或管理员）。
  2. `PROCESSING` 状态拒绝（409），避免边解析边删。
  3. 先删向量（`deleteByFileId`）→ 再删磁盘文件 → 最后删数据库记录。
- **`reindex(fileId, principal) → FileDto`**：重置为 `PENDING`、chunkCount=0、清错误信息，再触发一次异步解析（用于换了切分参数/解析失败重试）。
- **`pathForDownload(fileId, principal) → Path`**：可看才给路径；文件不在磁盘 → 404「原始文件已丢失」。
- **`getById(fileId) → KnowledgeFile`**：内部使用，不做权限判断（Controller 的 download 用它取原始文件名）。
- **`getManageable(fileId, principal)`**（private）：不存在 404；`canManage` 不通过 → 404。
- **`canView(file, principal)`**（static）：`PUBLIC` 或本人。**管理员也不能看学生私有资料正文**。
- **`canManage(file, principal)`**（static）：本人或管理员（管理员可删/可重建索引）。
- **`isAdmin(principal)`**（static）：`role` 等于 `"ADMIN"`。

> 设计要点：**“能管理” 和 “能看内容” 是两套规则**。管理员能删学生的私有文件，但下载/检索不到它的内容。

### 3.4 `file/FileStorageService.java`

只负责“文件怎么落盘”，不碰数据库。

- **`init()`**（`@PostConstruct`）：把 `app.storage.upload-dir` 转绝对路径并 `createDirectories`，失败直接让应用启动失败（比运行到一半才发现目录不可写要好）。
- **`store(MultipartFile) → StoredFile`**
  1. 空文件 → 400。
  2. 文件名 `sanitize`（取 basename、去控制字符）。
  3. 扩展名白名单：`.pdf .docx .doc .ppt .pptx .txt .md .markdown`，否则 400。
  4. 大小限制：`maxFileMb * 1024 * 1024`，超限 413。
  5. 存储名 = 32 位 UUID（去横线）+ 扩展名；`normalize()` 后必须仍在 `uploadDir` 下（防路径穿越）。
  6. `DigestInputStream` + `transferTo`：边写盘边算 SHA-256，避免二次读文件。
  7. 写失败 → 删半截文件 → 400「文件保存失败」。
  8. 返回 `StoredFile(originalName, storedName, extension, size, sha256)`。
- **`pathOf(storedName) → Path`**：拼接后再次校验前缀，防 `../`。
- **`delete(storedName)`**：`deleteIfExists`，异常吞掉（删文件失败不该阻断业务）。
- **`sanitize(name)`**（private）：`Paths.get(name).getFileName()` 去掉路径部分，再剔除 `\x00-\x1f` 控制字符，空则“未命名文件”。
- **`extensionOf(name)`**（private）：最后一个 `.` 之后，转小写。
- **`record StoredFile`**：落盘结果的值对象。

### 3.5 `file/FileIngestService.java`

**异步解析入库**，全项目最“重”的一段流程。

- **`processAsync(Long fileId)`**（`@Async("fileTaskExecutor")`）
  1. 查文件，不存在直接返回。
  2. 置 `PROCESSING` 并保存（前端轮询能看到状态变化）。
  3. **先删旧向量**：重传/重建时避免留下过期内容。
  4. `DocumentParser.parse(InputStream)`（Tika）抽文本；文本为空 → 抛 `BizException(PARSE_FAILED_MESSAGE)`（扫描版 PDF 就走到这）。
  5. `Document.from(text, buildMetadata(file))`：把 fileId、accessOwnerId 等写进每个 segment 的元数据。
  6. `documentSplitter.split(document)` 切块；空 → 解析失败。
  7. 给每块补 `chunkIndex`（0 开始），用于前端显示“第 N 段”。
  8. `embeddingModel.embedAll(segments)` 批量向量化；数量对不上 → 抛异常。
  9. `vectorStoreService.addAll(...)` 写 Chroma。
  10. 置 `READY`、`chunkCount`、清错误信息，保存，打日志。
  11. 任意异常：再删一次向量（尽力而为）→ `FAILED` + `errorMessage` → 保存。**不会把异常抛给调用方**（异步线程里抛了也没人接）。
- **`buildMetadata(KnowledgeFile) → Metadata`**：写 `fileId`、`accessOwnerId`（**公共资料固定 0**，私有资料为 ownerId）、`filename`、`visibility`、`fileType`。
- **`messageOf(Exception) → String`**：业务异常用原话；消息里带 `Tika` 的统一转成“解析失败”文案；其他给通用文案（细节进日志）。

> `accessOwnerId` 是权限过滤的基石：检索时只查 `0` 和“我”，从数据层面隔离私有资料。

### 3.6 `file/KnowledgeFile.java`

实体，表 `knowledge_files`，3 个索引：`owner_id`、`visibility`、`status`。

| 字段 | 列 | 说明 |
|---|---|---|
| `id` | 主键 | 自增 |
| `ownerId` / `ownerName` | `owner_id` / `owner_name` | 上传者；名字冗余存一份，列表页不用再查 users |
| `visibility` | `visibility` | `PUBLIC` / `PRIVATE`，默认 PRIVATE |
| `originalName` | `original_name` | 原始文件名（展示、下载用） |
| `storedName` | `stored_name` | UUID 文件名（磁盘上的真实名字） |
| `fileType` | `file_type` | 扩展名去掉点，如 `pdf` |
| `fileSize` | `file_size` | 字节 |
| `sha256` | `sha256` | 内容指纹，用于秒传/去重 |
| `status` | `status` | `PENDING/PROCESSING/READY/FAILED` |
| `chunkCount` | `chunk_count` | 切块数量 |
| `errorMessage` | `error_message` | 失败原因（≤800） |
| `createdAt` / `updatedAt` | `created_at` / `updated_at` | 生命周期回调维护 |

- **`prePersist()`**：补 `createdAt`，刷新 `updatedAt`。
- **`preUpdate()`**：刷新 `updatedAt`。

### 3.7 `file/KnowledgeFileRepository.java`

全部是 Spring Data 派生查询，没有手写 SQL：

| 方法 | 用途 |
|---|---|
| `findByOwnerIdOrderByCreatedAtDesc` | 我的资料 |
| `findByVisibilityOrderByCreatedAtDesc` | 公共资料 |
| `findByVisibilityOrOwnerIdOrderByCreatedAtDesc` | 我可访问的资料 |
| `findByIdAndOwnerId` | 本人校验（预留） |
| `findByIdIn` | 批量按 id 查（预留） |
| `countByStatus` / `countByVisibility` | 统计（预留） |
| `existsBySha256AndOwnerIdAndVisibility` | 私有资料去重 |
| `existsBySha256AndVisibility` | 公共资料去重 |

### 3.8 `file/FileStatus.java`

`PENDING`（已接收）→ `PROCESSING`（解析中）→ `READY`（可检索）/ `FAILED`（失败）。前端按这个轮询展示。

### 3.9 `file/Visibility.java`

`PUBLIC`（全校可检索）/ `PRIVATE`（仅上传者）。

## 4. 向量检索（`rag`）

### 4.1 `rag/VectorStoreService.java`

对 `EmbeddingStore` 的唯一封装层，**检索权限过滤就写在这里**。

- **常量**：元数据键 `fileId`、`accessOwnerId`、`filename`、`visibility`、`chunkIndex`（与 FileIngestService 写入时保持一致）。
- **`addAll(List<Embedding>, List<TextSegment>)`**：直接透传给 store。
- **`deleteByFileId(Long)`**
  - 用 `metadataKey("fileId").isEqualTo(fileId)` 删除该文件所有向量。
  - Chroma 在 collection 还不存在时会报 not found / 404 → 视为正常，打 info 后返回（第一次上传时必然会遇到）。
  - 其他异常 → 503「向量库操作失败」。
- **`search(query, userId, fileIds, topK) → List<EmbeddingMatch<TextSegment>>`**
  1. 取 embedding key（`app.ai.embedding.apiKey`，空则回退 chat key）；都空 → 503。
  2. `embeddingModel.embed(query)` 把问题向量化。
  3. 过滤条件：`accessOwnerId in (0, userId)`——**公共 + 我的私有**，一条过滤把越权召回堵死。
  4. 若指定了 `fileIds`，再 `and(fileId in fileIds)`（前端“只针对这几份资料提问”）。
  5. `EmbeddingSearchRequest`：`maxResults=topK`、`minScore=app.rag.min-score`、带 filter。
  6. 返回 `matches()`。
  7. 业务异常原样抛；其他异常统一 503「知识库检索失败，请确认 Chroma 服务已启动」。

> 为什么过滤放在服务端：`fileIds` 是前端传的，如果只在应用层比较，恶意请求可以传别人的 fileId；把条件拼进向量查询，Chroma 返回的候选集里根本不会有越权数据。

## 5. 问答与复习（`chat`）

### 5.1 `chat/ChatController.java`

只有 **`ask(principal, @Valid ChatRequest) → ChatResponse`**：`POST /api/chat/ask`。
统一入口，方便以后加 SSE 流式输出（把返回类型换成 `SseEmitter` 即可）。

### 5.2 `chat/ChatDtos.java`

- **`ChatRequest(userId, question, conversationId, mode, fileIds)`**
  - `userId` 保留是为了兼容前端约定，**服务端会校验它必须等于登录人**。
  - `question` 非空且 ≤4000 字；`mode` 见 ReviewMode；`fileIds` 可空（空=全库检索）。
- **`ChatResponse(conversationId, messageId, answer, citations, mode, latencyMs)`**
  - `messageId` 是本次回答在 `chat_messages` 里的 id；`latencyMs` 从检索开始计时（固定话术的响应为 0）。

### 5.3 `chat/ChatService.java`（核心）

字段：4 个 Repository/Service + PromptBuilder + GuardService + ChatModel + AppProperties + ObjectMapper。
`FOLLOW_UP` 正则用来判断“是不是追问”（它/这个/上面/继续…）。

- **`ask(UserPrincipal, ChatRequest) → ChatResponse`** —— 整条问答主流程
  1. `request.userId()` 非空且不等于登录人 → 403（防越权）。
  2. 问题 `trim`，`ReviewMode.from(mode)` 解析模式（非法值回落 QA）。
  3. `resolveConversation`：有 `conversationId` 就按“id + 当前用户”查（查不到 404，防读别人会话）；没有就新建，标题取问题前 30 字。
  4. `loadHistory`：取最近消息作为上下文。
  5. **先保存用户消息**（`role=USER`，citations 存 `"[]"`）——即使后面模型失败，提问记录也留得住。
  6. `guardService.classify(question)`：
     - `HOMEWORK` → 固定拒答话术；
     - `GREETING` → 固定欢迎语；
     - `OUT_OF_SCOPE` → 固定“无法解答”；
     - `NORMAL` → 继续。
     固定话术直接保存 assistant 消息并返回，**不调用模型、不检索**（省钱、可控）。
  7. `ensureModelConfigured()`：chat key 为空 → 503；embedding key（或回退 chat key）为空 → 503。
  8. `normalizeFileIds`：去 null、去重、最多 10 个。
  9. `validateSelectedFiles`：逐个 `getAccessible`（越权 404），且状态必须 `READY`（否则 409）。
  10. `buildRetrievalQuery`：短问题或含追问词时，把上一轮用户问题拼在前面（≤200 字），解决“它/这门课”指代。
  11. topK 策略：QA 用配置值；复习类模式至少 8；指定了资料也至少 8；最后封顶 12。
  12. `vectorStoreService.search(...)` 检索。
  13. 无命中 → 保存并返回固定的 `NO_CONTEXT_MESSAGE`（`citations=[]`，`latencyMs` 为实际耗时）。
  14. `promptBuilder.build(...)` 组系统提示词 + 历史 + 本次问题，得到 `PromptResult`。
  15. `chatModel.chat(messages)` 调模型；异常 → 502「模型服务暂时不可用…」；空回答 → 兜底文案。
  16. `saveAssistant` 保存回答 + 引用 JSON，更新会话 `updatedAt`。
  17. 返回 `ChatResponse`（含 citations 和耗时）。
- **`resolveConversation(principal, conversationId, question)`**（private）：查/建会话，标题截断 30 字。
- **`loadHistory(conversationId)`**（private）：`findTop12...OrderByIdDesc` 取最近 12 条 → `reverse()` 变正序 → 按 `historyMessages`（≥2）截取尾部。
- **`normalizeFileIds(raw)`**（private）：过滤 null、distinct、`limit(10)`。
- **`validateSelectedFiles(principal, ids)`**（private）：可访问 + `READY`，否则 404/409。
- **`buildRetrievalQuery(question, history)`**（private）：无历史直接返回；问题 <15 字或命中 `FOLLOW_UP` 才拼接上一问。
- **`saveAssistant(conversation, answer, citations)`**（private）：保存消息（citations 用 Jackson 序列化，失败兜底 `"[]"`）；刷新会话时间；返回保存后的实体。
- **`ensureModelConfigured()`**（private）：两个 Key 的兜底校验，错误信息直接告诉用户去 `.env` 填哪一项。

### 5.4 `chat/PromptBuilder.java`

把“检索结果 + 历史 + 模式指令”拼成 LangChain4j 的消息列表，同时产出引用列表。

- **构造器 `PromptBuilder(ResourceLoader)`**：从 classpath 读 `prompts/system-prompt.txt`（UTF-8），读不到直接启动失败（提示词是核心资产，不能静默降级）。
- **`MODE_INSTRUCTIONS`**（静态 Map）：6 种模式各自的任务描述（问答 / 总结 / 划重点 / 讲解 / 出题 / 多资料整合）。改这里就能调“回答风格”。
- **`build(question, mode, matches, history, maxContextChars) → PromptResult`**
  1. `buildContext` 生成上下文和引用。
  2. 把模板里的 `{{RAG_CONTEXT}}` 替换成上下文。
  3. 消息顺序：`SystemMessage`（模板）→ 历史（USER→UserMessage，ASSISTANT→AiMessage）→ 本次 `UserMessage`（含模式指令）。
  4. 返回 `PromptResult(messages, citations)`。
- **`buildContext(matches, maxContextChars) → ContextResult`**
  - 逐条处理：跳过空 segment；从 metadata 取 `fileId`、`filename`、`chunkIndex`。
  - 去重键 = `fileId + ":" + 前100字`，避免同一段被重复召回。
  - 字符预算：**至少保留第一条**，之后超过 `maxContextChars` 就停。
  - 引用编号从 1 开始，`score` 空则 0；snippet 截 180 字。
  - 拼成 `[1] 来源：《文件名》（第 N 段），相关度 0.86\n内容：...\n---\n` 的格式。
  - 一条都没有 → 上下文写“（本次未检索到相关资料）”。
- **`buildUserMessage(question, mode)`**（private）：`【用户提问】…\n【本次任务】…` 的模板。
- **`numberToLong(value)` / `numberToInt(value)`**（private）：metadata 里的数字可能是 Integer/Long/Double，统一转换。
- **`truncate(text, limit)`**（public static）：超长截断并加 `…`，`null` 返回空串。
- **`record ContextResult(context, citations)`**、**`record PromptResult(messages, citations)`**。

### 5.5 `chat/GuardService.java`

关键词/正则护栏，**在调模型之前**做意图分类，保证固定话术稳定、可测。

- **`enum Intent { HOMEWORK, GREETING, OUT_OF_SCOPE, NORMAL }`**
- **常量话术**：`NO_CONTEXT_MESSAGE`、`HOMEWORK_REFUSAL`、`OUT_OF_SCOPE_ANSWER`、`GREETING`（改这里就是改“固定回复”）。
- **规则表**
  - `HOMEWORK`：帮我/替我/给我 + 写/做/生成/完成/代写 + 作业/论文/报告/试卷…；完整答案；代写；论文全文。
  - `OUT_OF_SCOPE`：游戏、情感、时政股票、写诗写小说、leetcode/编程题、闲聊。
  - `GREETINGS`：整句只有“你好/hi/在吗/谢谢/收到”等。
- **`classify(message) → Intent`**：空串 → NORMAL；顺序是 **HOMEWORK → GREETING → OUT_OF_SCOPE**（作业类优先，避免“帮我写作业”被当成普通请求）。
- **`matches(patterns, text)`**（private）：任一正则 `find()` 命中即真。

> 护栏是“宁可误拒”的保守策略，改规则时建议同步改 `GuardServiceTest`。

### 5.6 `chat/ReviewMode.java`

`QA / SUMMARY / KEYPOINTS / EXPLAIN / QUIZ / INTEGRATE`，每个带中文 `label`（前端展示用）。

- **`label()`**：返回中文名。
- **`from(String)`**（static）：空/非法 → `QA`，大小写不敏感。

### 5.7 `chat/Citation.java`

`record Citation(int index, Long fileId, String filename, Integer chunkIndex, double score, String snippet)`。
**引用来源**，前端渲染成“《文件名》第 N 段（相关度 0.86）”。

### 5.8 `chat/ChatConversation.java`

实体 `chat_conversations`，索引 `user_id`。

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `userId` | 归属用户（隔离依据） |
| `title` | 会话标题（首问前 30 字） |
| `createdAt` / `updatedAt` | `@PrePersist` / `@PreUpdate` 维护 |

- **`prePersist()`**：同时填创建/更新时间。
- **`preUpdate()`**：刷新更新时间（每次问答都会调）。

### 5.9 `chat/ChatMessage.java`

实体 `chat_messages`，索引 `conversation_id`。

| 字段 | 说明 |
|---|---|

### 6.1 `common/BizException.java`

业务异常，携带 HTTP 状态码。

## 9. 关键调用链

### 9.1 登录

```text
POST /api/auth/login
 → AuthController.login
 → AuthService.login
    → UserRepository.findByUsername
    → BCrypt.matches
    → JwtService.generate
 ← { token, user }
```

### 9.2 上传并入库

```text
POST /api/file/upload
 → FileController.upload
 → FileService.upload
    → FileStorageService.store（落盘 + SHA-256）
    → 去重检查 → 建 KnowledgeFile(PENDING)
    → FileIngestService.processAsync（异步，立即返回）
 ← UploadResponse

异步线程 file-ingest-*:
 PROCESSING → 删旧向量 → Tika 解析 → 切分(+chunkIndex) → embedAll → Chroma.addAll
 → READY / FAILED
```

### 9.3 提问

```text
POST /api/chat/ask
 → ChatController.ask
 → ChatService.ask
    → 校验 userId、解析 mode
    → 会话（查/建）+ 历史消息
    → 保存用户消息
    → GuardService.classify ──(固定话术)──→ 直接返回
    → ensureModelConfigured
    → 校验 fileIds（可访问 + READY）
    → 拼检索 query（追问补上下文）
    → VectorStoreService.search（accessOwnerId in (0, me)）
    → 无命中 → NO_CONTEXT_MESSAGE
    → PromptBuilder.build（系统提示词 + 历史 + 模式指令）
    → ChatModel.chat
    → 保存回答 + citationsJson，更新会话时间
 ← ChatResponse(answer, citations, latencyMs)
```

### 9.4 删除资料

```text
DELETE /api/file/{id}
 → FileService.delete
    → getManageable（本人或管理员；PROCESSING 拒绝）
    → VectorStoreService.deleteByFileId
    → FileStorageService.delete
    → KnowledgeFileRepository.delete
```

## 11. 设计取舍与已知限制

1. **没有 `@Transactional`**：上传/删除是“多存储”操作（MySQL + 磁盘 + Chroma），无法用单机事务覆盖，所以靠“先删向量再删记录”的顺序和状态字段保证最终一致；极端情况下可能残留孤儿数据，用 `reindex` / 手动清理兜底。
2. **管理员权限有边界**：能删、能重建索引，但**看不到**学生私有资料正文（`canView` 只认公共或本人）。
3. **JWT 无状态**：改密码、删用户都不会让旧 token 立即失效；要强制下线只能轮换 `JWT_SECRET`（所有人一起掉线）。
4. **异步入库无重试**：失败即 `FAILED`，需要用户点“重新入库”或重新上传。
5. **去重靠查询、不是唯一索引**：两个并发请求同时上传同一文件，理论上都可能通过查重（概率低，若要严格可加 `(sha256, owner_id, visibility)` 唯一索引）。
6. **列表接口没有分页**：资料多了会一次性返回，后续可加 `Pageable`。
7. **`memory` 向量库仅用于本地**：进程重启即清空，生产必须用 Chroma。
8. **Guard 是基于正则的规则**：语义变体可能漏判（如“帮我整理一份作业答案”），属于演示级护栏，不是内容安全方案。
9. **`HealthController` 只检查 Key 非空**：不能当作“模型可用”的探针，真实可用性要看一次问答是否成功。
10. **上传后立刻返回**：前端必须轮询状态，不能假定上传完就能提问。

## 12. 阅读顺序建议

1. `CampusKbApplication` → `AppProperties` → `application.yml`（先搞清配置怎么进来）
2. `AuthController` → `AuthService` → `JwtService` → `JwtAuthenticationFilter` → `SecurityConfig`（认证闭环）
3. `FileController` → `FileService` → `FileStorageService` → `FileIngestService`（上传链路）
4. `VectorStoreService` → `PromptBuilder` → `ChatService`（检索与问答）
5. `GuardService` / `ReviewMode`（行为边界）
6. `GlobalExceptionHandler` / `BizException`（错误约定）
